# Research figures

Deterministic, publication-quality charts generated from VeriGate's
sanitized campaign analysis output
(`research/results/8449581e-4097-4865-bfae-5cd8e9aef83f/`). Generated by:

```bash
cd backend
source .venv/bin/activate
python -m experiment.cli generate-figures
```

This command (`experiment.figures.generate_all_figures`, called from
`experiment.cli`) reads **only** the sanitized, already-committed
`research/results/<campaign_id>/candidate_results.csv` and
`condition_summary.csv` files. It never reads anything under
`backend/data/` (raw campaign/candidate/experiment artifacts), never
initializes a reviewer/generator provider, and never makes a network
call. Re-running it against unchanged source files produces
byte-identical PNG/SVG output (see
`backend/tests/test_figures.py::TestRealCampaignData::test_generate_all_figures_writes_six_files_with_canonical_hashes_stable`).

Every number in every chart below is a straight read of a
`research/results/` CSV column -- nothing is hardcoded in the generator
and nothing is recomputed from raw data.

## Important framing (read before interpreting any chart)

- The **eligible set (n=4)** is **package_resolver-only** and was produced
  under the **transparently disclosed post-data adjudication amendment**
  (`docs/research_protocol.md`, "Amendment 1" -- added *after* all data
  had already been collected). The A/B/C experimental conditions and the
  primary/secondary estimand were preregistered; the specific rule that
  decides *which* candidates are eligible was not. Never describe the
  n=4 result as simply "the preregistered primary analysis."
- The **complete 12-candidate descriptive cohort** does not depend on
  that eligibility rule at all -- every one of the 12 qualifying
  candidates is always included in it, regardless of adjudication
  category.
- This is an exploratory study (n\u226412 candidates). No chart here implies
  statistical significance, causality beyond this controlled setting, or
  generality across coding tasks or reviewer models.

## Charts

### `condition_confidence.png` / `.svg`

Mean A/B/C reviewer confidence for two populations, shown as grouped bars
with explicit `n=` labels:

- **Eligible set** (`n=4`, package_resolver only, post-data amendment) --
  green bars.
- **Complete descriptive cohort** (`n=12`, all candidates) -- blue bars.

**Source fields:** `condition_summary.csv`, rows with `task_id=ALL`, for
`scope=primary_eligible` and `scope=full_cohort`, column
`mean_confidence` per `condition`.

**How to read it:** the two populations are intentionally kept visually
and numerically separate (different colors, different `n`, a disclosure
caption) because they answer different questions -- one is a small,
post-data-filtered subset of a single task, the other is every candidate
this campaign ever produced.

### `candidate_effects.png` / `.svg`

Per-candidate `B-A` (visible-pass effect) and `C-B` (adversarial-review
effect) for all 12 qualifying candidates, as two stacked bar panels
sharing a candidate axis, each with a zero reference line.

**Source fields:** `candidate_results.csv`, columns
`qualification_index` (rendered as short public-safe labels `Q0`-`Q11`,
never a raw candidate UUID), `task_id`, `b_minus_a`, `c_minus_b`,
`eligible_for_primary_analysis`.

**How to read it:**

- **Color** distinguishes task: blue = `json_parser`, orange =
  `package_resolver`.
- **Hatching + edge weight** (not color alone) distinguish eligibility:
  a diagonal hatch and a heavier black outline mark the 4 candidates
  eligible for the primary analysis; a plain fill and a thin gray outline
  mark the 8 excluded (`benchmark_mismatch` / `ambiguous`) candidates.
- Candidates are ordered by `Q0`-`Q11` (chronological qualification
  order), never sorted by effect size.

### `adjudication_breakdown.png` / `.svg`

A labeled horizontal bar chart (deliberately not a pie chart) of how many
of the 12 qualifying candidates fall into each adjudication category:
`valid_pass`, `valid_failure`, `benchmark_mismatch`, `ambiguous`.

**Source fields:** `candidate_results.csv` column `adjudication_status`,
counted per category (a category with zero candidates -- `valid_pass` in
this campaign -- is still shown explicitly, not omitted).

**How to read it:** green bars (`valid_pass`, `valid_failure`) are the
categories eligible for the primary analysis; gray bars
(`benchmark_mismatch`, `ambiguous`) are excluded from it. Every one of
the 12 candidates falls into exactly one category, and every candidate's
raw benchmark result is still reported unchanged regardless of category
(see `docs/research_protocol.md`'s adjudication policy).

## Design choices

- **Colorblind-conscious palette**: colors are drawn from the
  [Okabe-Ito](https://jfly.uni-koeln.de/color/) palette (blue, orange,
  bluish green, sky blue, neutral gray), and every chart that encodes a
  binary distinction (task, eligibility, adjudication) also uses a
  second visual channel (hatching, edge weight, or explicit text labels)
  so the distinction survives grayscale printing or color-vision
  deficiency.
- **Legible at GitHub README width**: fonts are sized well above
  matplotlib defaults so labels remain readable after GitHub's
  README-width downscale.
- **No 3D effects, no decorative chartjunk**: plain bar/horizontal-bar
  charts only.
- **Deterministic output**: a fixed headless (`Agg`) backend, a fixed
  `svg.hashsalt` (otherwise matplotlib's SVG backend embeds
  memory-address-derived ids), and fixed PNG/SVG metadata with no
  timestamp, absolute path, API identifier, or hidden-test content. See
  `experiment.figures`'s module docstring for the full determinism
  rationale.

## Regenerating

```bash
cd backend
source .venv/bin/activate
python -m experiment.cli generate-figures
```

Optional flags: `--results-dir` (default `research/results/`) and
`--output-dir` (default `research/figures/`). The command never modifies
any file under `research/results/` or `research/adjudications.json` --
it only writes new files under the target figures directory.
